作業名の頭に「想定ユーザー（誰・何回目）」を付けてあります。

## 入れ方（Mac）

1. この zip を展開する
2. 出てきた `2026110…` で始まるフォルダ（10）を、`kiyaku-kaisei/private/work/` にそのまま入れる
3. ブラウザでトップ画面を再読み込みする（サーバーの起動し直しは要らない）

見るところ：作業の画面の上の「状態」・各ステップ、指摘や議題の「判断の履歴」、
処理中の「作業の記録」（作業の記録は work.json の log にも残っています）、
ステップ3の「AI の費用」、写真の書き込みの読み取り（ステップ3・4の写真の欄）。

## 作業ごとに、何をしたか

### 佐藤さん 1回目（標準管理規約）
- 推奨を2〜3件「改定案に入れる」→ 改定案 → 検討資料 → 説明 → 総会の結果
- 見つかったこと：「確定する」を押し忘れて「役員の欠格条項」が改定案から抜けた／推奨の議題が「①必ず必要」に入り見送れない

### 田中さん 1回目（Word の規約集）
- 第21条を手で直して AI に確かめてもらう／写真の書き込み（取り消し線）を反映／②を「修正して採用」→ 対象の条だけ作り直す
- 見つかったこと：委員会で直したのに資料が「ほかは変えていない」と書く／確かめる役が委員会の意見に「削除して」と言う

### 鈴木さん 1回目（古い規約）
- 点検中・改定案の作成中にブラウザを閉じて戻る／まとめて判断／理事会で「役員の欠格条項」を見送り
- 見つかったこと：見送った条が新旧対照表に残る／理事会の判断が再読み込みで消える

### 佐藤さん 2〜5回目（標準管理規約）
- 推奨3件を入れ、1件見送り → 改定案 → 理事会で議題4（第47条の定足数）を見送り → 対象の条だけ作り直す（第47条だけ「半数以上」に戻る）→ 説明 → 総会
- 4回目：議題4を「採用」に戻して作り直し（第47条が「過半数」に戻る）。総会の結果を記録したあとの変更で、注意が出ることを確認
- 5回目：説明文を作り直し

### 田中さん 2〜6回目（Word の規約集）
- 第38条の2 の文・理由・補足を手で直す／写真の書き込みを何度か反映（補足が日付つきで書き足されていく）
- ②の議題5を「修正して採用」→ 対象の条だけ作り直す。議題6の見送り⇔採用を変えて、作り直しの案内が出る・消えることを確認

### 鈴木さん 2回目（古い規約）
- 問2で案を選んで作り直したら、新しい〔選択〕が出て2回作り直しが要った（残る課題）

### 鈴木さん 3〜5回目（細則を含む規約集）
- 推奨1件を個別に見送り → まとめて判断（まだ決めていないものだけ）→ 改定案 → 検討資料 → 判断をすばやく選んで移動しても消えないか → 作り直し → 説明 → 総会
- 4回目：判断を変えて元に戻しても作り直しが残る不具合を見つけた（直した）。5回目：説明文を作り直し

詳しい経緯と、直したこと・残る課題：リポジトリの docs/plans/想定ユーザーでの確認_1105.md
