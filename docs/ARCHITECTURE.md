# 技術構成（ARCHITECTURE）

11/2 に、Anthropic 公式ドキュメント（Claude API / Managed Agents）をもとに作成し、同日承認された。
当初は 11/3 の公式セッションを見てから決める予定だったが、ドキュメントで確認できたため前倒しした。

## 結論
**決定的な処理は自前のコード、判断が要る処理は Managed Agents** に分ける構成にする。

| 処理 | 担当 | 理由 |
| --- | --- | --- |
| 規約の取り込み（docx・PDF・テキスト）、条・項への分割 | 自前のコード（Python） | 毎回同じ結果になるべき処理。AI に任せる必要がない |
| 見え消し Word の解析、評価の採点 | 自前のコード（Python） | 評価は再現できることが最優先 |
| 条文の突き合わせ、指摘（根拠・区分・規約か細則か）の作成 | **Managed Agents** | 条ごとに資料を引きながら判断する、エージェント向きの作業 |
| 改定案・新旧対照表・住民向け説明の作成 | **Managed Agents（Outcomes）** | 評価基準（ルーブリック）を満たすまで、別の採点役が繰り返し直させられる |
| 判断の記録（採用・不採用・理由）の正本 | 自前のコード（ローカルの JSON / SQLite） | 画面から編集する。非公開データを手元に置ける |
| 画面 | 自前の Web アプリ（FastAPI と HTML） | Streamlit は使わない。画面はすべて日本語 |

## Managed Agents を使う理由
1. **Claude の活用（審査の25%）を見せやすい**：エージェントが条文ごとに資料を引いて判断する様子が、イベントの流れとしてそのまま見える。Console のセッション画面でも、記録・ツールの使用状況・費用を確認できる
2. **改正知識をスキルにできる**：DOMAIN.md の論点表、標準管理規約、区分所有法を、カスタムの **Skill** としてエージェントに持たせる（BRIEF の「改正知識のスキル化」）
3. **Outcomes で品質を担保する**：「必須の論点がすべて入っている」「すべての指摘に根拠条文がある」「下書きであり法的助言ではないと明記している」などのルーブリックで、別の採点役が合格するまで直させる
4. **エージェントの設定を版で管理できる**：エージェントの設定は版付きで保存され、セッションは特定の版で動く。プロンプトを変えたときに evals/ で前後の版を比べられる
5. **11/3 のセッションのテーマと一致している**

## 自前の部分（Messages API ではなく自前のコード）にする理由
- 評価（必須の再現率100%など）は何度も回すので、決定的な前処理と採点を AI から切り離す
- 実際の規約（非公開）の本文は、**カスタムツール**でアプリ側から必要な条だけを渡す。Files API に規約全体を上げないので、手元から出るのは処理に必要な範囲に限られる

## 構成図
```
[画面（ブラウザ）]
   │  規約のアップロード、基本情報の入力、指摘の採用・不採用
   ▼
[アプリ（FastAPI, Python）]─────────────┐
   │ 取り込み・条文分割（決定的）          │ 判断記録（JSON/SQLite、正本）
   │ 評価・採点（evals/）                 │
   ▼                                      │
[Managed Agents セッション] ◀─ カスタムツール ─┘
   ├ Agent：claude-opus-5-5（版で管理）
   ├ Skill：改正論点（DOMAIN）、標準管理規約（単棟型）、区分所有法
   ├ カスタムツール：get_article（現行規約の条）、get_decisions / record_finding
   └ Outcome：改定案・新旧対照表・住民向け説明をルーブリックで採点
```

## 使う機能と注意点（公式ドキュメントで確認済み）
- Managed Agents は**ベータ**（ヘッダー `managed-agents-2026-04-01`、SDK が自動で付ける）。Claude API で使える
- 流れは「Agent を1回作る → 実行ごとに Session を作る」。Agent はファイルで定義し、`ant apply` で同期する
- 料金：モデルのトークン料金に加えて、セッションの実行時間が **$0.08/時間**。セッションごとに**上限金額（budget）**を設定できるので、評価を回しても費用が膨らまない
- モデル：`claude-opus-5-5`（入力 $4／出力 $20、100万トークンあたり）。拒否時の自動フォールバック（`fallbacks`）を有効にする
- Memory Store（セッションをまたぐ記憶）もあるが、MVP では使わない。判断記録の正本は画面から編集するのでアプリ側に置き、必要な分をカスタムツールで渡す
- 条文ごとに複数のエージェントへ分担させる機能（multiagent workflows）は、トークンを多く使うため MVP では使わない。精度や速度が足りないときに検討する

## 開発環境
- 言語：Python 3.13（docx・PDF の処理と評価に向く）、パッケージ管理は uv
- SDK：`anthropic`（公式）
- APIキー：手元のPCでは `.env` の `ANTHROPIC_API_KEY`（コミットしない）。Claude Code のクラウド環境では環境変数 `KIYAKU_ANTHROPIC_API_KEY`（`ANTHROPIC_API_KEY` という名前は Claude Code 自身の認証用に扱われ、セッションに渡らないため）。読み込みは core/config.py
- 11/2 に、この構成のキーで Messages API の呼び出しと Managed Agents（ベータ）の利用ができることを確認済み

## ディレクトリ構成
```
app/           画面とAPI（FastAPI）
  templates/   画面（Jinja2）。作業の画面は work.html が骨組みで、ステップごとの中身は work/step1_review.html〜step6_meeting.html
  static/      デザインシステムの正本（tokens.css・components.css）と、アプリ固有の見た目（app.css）
core/          取り込み・条文分割・新旧対照表の組み立て（決定的な処理）
agents/        Managed Agents の定義ファイル（ant apply で同期）
skills/        改正知識のスキル（DOMAIN の論点表、条文の引き方）
evals/         正解データの作成（見え消しの解析）と採点
data/public/   公開資料（出典は SOURCES.md）
private/       非公開データ（.gitignore 済み、コミットしない）
```

## 決めたこと（11/4）
- 画面は、サーバーで組み立てる HTML（Jinja2）と CSS、少しの JavaScript（判断の保存・絞り込み・ステップの切り替え）。htmx や React は使わない

## API キーとエージェントの登録（11/5 追加）
- 管理組合が自分の API キーで使う前提。エージェントは API キーのワークスペースごとに登録が要るので、agents/registry.py が使うキーを見て選ぶ
  - リポジトリの agents/state.json の登録が見えるキー（開発者）：そのまま使う
  - 見えないキー：初めて点検・改定案づくりをするときに agents/setup.py の `ensure` で登録し、ID を private/agents/ に保存（キーの指紋をファイル名に使い、キーそのものは保存しない）
  - スキル・指示文・道具・モデルの指紋が変わったら、自動で登録を更新する

## 単発の AI 呼び出し（11/4〜5 追加）
点検・改定案は Managed Agents だが、次の2つは1回で済む作業なので Messages API（`messages.stream`、構造化出力、`fallbacks`）を直接呼ぶ。どちらも人が押したときだけ動き、結果は人が選んでから反映する。
- 書き込みの読み取り（core/notes.py）：印刷した資料の写真から手書きの書き込みを読み、反映の提案にする。写真1枚 約$0.04〜0.09
- 直した文の確認（core/editcheck.py）：委員会が手で直した条の文を、AI の元の文・指摘・根拠の条文と見比べ、法律に合わないおそれなどを根拠付きで返す。根拠のない指摘は落とす。1条 約$0.03〜0.11
- 理事会の判断の部分的な反映（core/partial.py、11/5 追加）：理事会で〔選択〕の案を選んだ・「修正して採用」にした議題の条だけを書き直し（1回）、別の呼び出しで直した条とそれを参照する条を確かめる（1回）。条番号・文書・改正の別は AI に変えさせず、改定案全体を機械的に検査して、新しく出たエラーがあれば反映しない。全体の作り直し（Managed Agents、20〜45分・数ドル）に対し、架空サンプルの4条で 79秒・約$0.37。全体の作り直しも「全体を作り直す」として残す
