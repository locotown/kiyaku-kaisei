# コストの整理（メモ。提出前に整理する）

11/4 ユーザーのメモ：使うたびに AI の費用がかかる。実際に使ってもらうなら、コストを意識しないと実用に向かない。
審査の要素になるなら、提出前にコストを整理する。場合によっては、使うときの費用を下げる仕組みを考える。

## 審査基準との関係（docs/BRIEF.md）
- インパクト（30%）：専門家（マンション管理士・弁護士）に頼む費用と比べて、どれだけ安く・早くできるか
- Claude の活用（25%）：必要なところに必要なだけ AI を使っているか（検証ループで費用が下がったことも示せる）
- 深さと実行（20%）：費用を測って記録していること

## これまでに測った費用（progress.md・evals の記録から。モデルは core/config.py の MODEL）
| 処理 | 費用 | 時間 | 例 |
| --- | --- | --- | --- |
| 点検 | 約 $0.8〜1.0 | 3〜4分 | 標準管理規約・架空の古い規約・架空の規約集 |
| 改定案 | 約 $1.4〜3.8 | 8〜12分 | 採用件数で増える。指摘24件すべて採用：$3.84 → 検証ループ L1・L2 のあと $2.64 |
| 理事会の検討資料・住民向けの説明 | 1回 数セント〜数十セント | 数分 | |
| 一通し（点検〜説明） | 約 $2〜10 | 15〜50分 | 画面の案内に出している目安。理事会の判断で改定案を作り直すと、その分も加わる |

- 改定案の上限：採用8件まで 30分・$5、それより多いと 50分・$9（core/progress.py）
- 画面に、処理ごとの費用と合計を出している（改定案の「AI の費用」）

## 整理すること（提出前）
- 1つの管理組合が見直しを1回通すと、合計いくらか（作り直しを含めた現実的な幅）
- 専門家に頼む場合の費用との比べ方（出典のある数字にする。BRIEF では「要確認」のまま）
- 誰が費用を払う前提か（組合の API キー／サービスとして提供する場合）

## 費用を下げる案（未決定。効果と手間を見て選ぶ）
- 標準どおりの条は、国の改正文を下書きにする範囲を広げる（L1。すでに $3.84 → $2.64 の実績）
- プロンプトキャッシュ（毎回同じ条文・スキル・確認基準を送っている部分）
- 処理ごとにモデルを選ぶ（点検の照合や説明文など、軽い処理を小さいモデルに）。精度は evals/ で確かめる
- 採点役の確認を、1回目で合格しやすくする（差し戻しの回数が費用に効く。L2 の「よくある誤り」の追加）
- 使う前に費用の見込みを出し、上限を超えそうなら推奨・参考を絞るよう案内する（今も目安は出している）
- 急がない処理を Batch API にまとめる（安いが、結果が出るまで時間がかかる）

料金の単価や割引率は、使う前に公式の資料で確かめる（覚えている数字で書かない）。
