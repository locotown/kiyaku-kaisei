# 検証ループの計画（案）

11/3 ユーザーの提案：「事例が増えるほど精度が上がり、費用も減る」仕組みを組み込めないか。
この文書は承認前の計画。実装は承認後（CLAUDE.md「大きな変更は計画を示して承認を得てから」）。

## いま手元にある「答え合わせの材料」
| 材料 | どこにあるか | 何が分かるか |
| --- | --- | --- |
| 採点役の「直しが必要」の理由 | 改定案の記録（draft_evaluations） | AI が繰り返す誤りの型 |
| プログラムの自己点検のエラー・注意 | check_draft の記録 | 機械的な誤り（欠番、参照先、数値） |
| 委員会の不採用の理由 | 指摘の判断の履歴 | 指摘が誤りだったか（または方針として採らないか） |
| 理事会の「修正して採用」「要修正」、総会の「修正して可決」の文 | 理事会・総会の記録 | 人が直した最終の文（その組合にとっての正解） |
| 評価データ | evals/（公開）、private/（非公開） | 変更で精度が上がったか下がったか |

実例（11/3 時点）：実際に作った改定案2件で、採点役の差し戻しは「項目4：指摘と関係のない文言を変えた」が2件中2件、「項目9：参照が改定後の規約と合わない」が2件中1件。同じ型の誤りが繰り返されている。

## 3つのループ
### L1：標準どおりの条は、国の改正文を使う（決定的。費用と時間が減る）
- 現行の条が、改正前の標準管理規約と本文まで一字一句同じなら、国が公表した改正後の条文を改定案の下書きにする（AI は書かずに確認だけする）
- 標準に近い規約ほど、速く・安く・正確になる。国交省の調査では、規約を改正したことがある組合の約7割が、いずれかの版の標準管理規約に「概ね」沿っている（令和5年度マンション総合調査 20③：35.9%＋35.0%）。ただし、一字一句同じ条がどれだけあるかは、実際の規約で測るまで分からない
- 実測（11/3）：改正前の標準そのものなら、改正で変わった26条すべてが該当。架空の古い規約・規約集でも74条中14条が一字一句同じ
- 注意：電磁的方法などの〔選択〕は国の案のまま両案を示す。条番号の参照は自己点検（check_draft）で確かめる

### L2：よくある間違いを、次の作成の注意書きにする（1回目で合格しやすくなる）
- 採点役の差し戻し理由と自己点検のエラーを、確認項目ごとに集計するスクリプトを作る（evals/lessons.py）
- 繰り返す型（例：項目4・9）を「注意書きの候補」として出す → **人が承認** → スキル（skills/kiyaku-kaisei/SKILL.md）に足す → **評価で悪化しないことを確かめてから**採用する
- 1回目で合格すれば、採点役の2回目（実測で約$1〜2・5〜10分）が要らなくなる

### L3：人の判断を、評価データに貯める（非公開）
- 不採用の理由に「指摘が誤り」と「方針として採らない」を分けて選べるようにする（1つの組合の方針を、誤りとして学ばないため）
- 「指摘が誤り」と、理事会・総会で直した文を、private/ の評価データに貯める。スキルや確認基準を変えるたびに、公開の評価と一緒に回す（公開するのは数字だけ）

## 守ること
- スキルや確認基準を自動では書き換えない（人の承認と評価の確認を挟む）
- 実在の規約の文はスキル・公開の評価データに入れない（誤りの「型」だけを書く）
- 根拠を示せない注意書きは足さない（区分所有法の条文、標準管理規約の条番号）
- 出力は総会提案の下書きであり、法的助言ではない、のまま
