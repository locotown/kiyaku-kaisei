# 改正の方針：一部改正（A）と全部改正（C）、ツールがすること・人がすること（11/7 作者の判断）

作者が自分の規約集（実在。内容はここに書かない）で構成表を試し、「原本をどこまで使い、どこまで残すのか」「標準管理規約をベースに今の規約を合わせ込むことはできるのか」を話し合って決めた。

## 進め方：2段階

1. **まず A（一部改正）**：法改正で必要な変更（食い違うと効力を失うおそれがあるもの）を、次の定期総会で一部改正として通す。β版のツールがするのはこれ
2. **次に C（全部改正）の準備**：その後1〜2年かけて、標準管理規約をベースにした全部改正を準備する。説明会を重ね、意見が割れそうな点は別の議案に分ける
   - ツールでは、計画E（今の規約と標準管理規約の条の対応表、独自の規定を「標準にする・今のまま・独自で残す」と記録）が材料になる
   - 「標準ベースの全部改正案」まで伸ばすのは、正規版の機能の候補（β版ではしない）

総会の決め方は、A でも C でも同じ特別決議（改正後は、組合員総数・議決権総数の各過半数の出席で、出席者の各4分の3以上）。C が難しいのは決め方ではなく、合意の量（全条の説明、1つの議案だと1か所の反対で全体が否決されるおそれ、独自の規定を条ごとに決める作業）。

## A でツールがすること

改定案の条は次の3種類だけ。これ以外の条は一字一句変えない（古い言い回しや原本の誤記に気づいても直さず、「範囲外で気づいた点」として知らせる）。

| 種類 | 中身 |
| --- | --- |
| 改正 | 法改正で必要な変更（必須）と、理事会が採用した推奨の変更（標準管理規約の改正に合わせる任意の変更） |
| 新設 | 今の規約にない条を、枝番で足す（条番号は振り直さない） |
| 削除 | 改正法と食い違い、残すと矛盾する条 |

- 上の変更で条や項の番号がずれれば、それを引いている別の条の番号も直す（参照合わせ）
- 細則の条も同じ3種類で直し、規約（特別決議）と別の議案（普通決議）にする
- 別表を変える改定は作らない（条の形でないため）

## 総会のあとの「最新の規約」：ツールがすること・人がすること

ツールがすること（ステップ6）
- 原本の文に、総会で可決した改定だけを差し込んで、規約全体を組み立てる（Word と画面）。附則（施行日）を足す
- 今の規約に残る両案（（ア）（イ））は、理事会で選んだ案だけを残せる。「○」の空欄は、入れた数字が入る
- 規約集の改正履歴に足す一行を出す
- **別表・別紙・様式は入れない**。表の形（罫線・列）を再現できないため、「別表第1・別表第2…は、今回の改正はありません。原本のとおりです」と書く（11/7 作者の判断（b））。別表のあとに綴じられている資料（管理費の表・使用料の表・ルールなど）も同じ扱い
- **規約の前に書かれた作業用の説明は入れない**（委員会の注記など）。題名・目次のような短い行と、「。」で終わる前文（「管理規約第17条の規定に基づいて…定める。」）は残す。外したものはステップ6で知らせる

人がすること
- 体裁を元の規約集に合わせて整える（字下げ・条番号の書き方）
- 別表・様式などは、原本のページをそのまま綴じる
- 組合の慣行に合わせて綴じる（原本はそのまま、改正は冒頭の一覧表に書き足す形なら、一覧表に一行足し新旧対照表を添える／現に有効な規約の内容を記載した書面を作り直すなら、最新の規約の Word を使う）
- 総会の議事録の文言と照らし合わせる

## 入力についての前提

ツールが正しく動く前提は、入力が「改正を全部反映した、今有効な内容」であること。規約集が「本文は改正前、改正は冒頭の一覧表だけ」という形だと、そのまま読み込むと古い文で点検してしまう。重ね合わせは、議事録を確かめる必要もあり自動化しにくい（作者の組合では、委員会が作業用資料として作った）。読み込みの段階で「この版は今有効な内容か」を確かめる案内を置くことは、今後の課題。
